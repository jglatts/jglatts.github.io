Writing a Serial Keyboard Wedge for Windows

By John Glatts

A serial keyboard wedge is one of those tools that sounds boring until you need it.

Then it becomes the difference between fighting with copy/paste all day and having production data exactly where it needs to go.

The idea is simple: read data from a serial device, process it if needed, and send it to the active Windows application as if someone typed it on a keyboard.

Scales, balances, gauges, meters, barcode scanners, and sensors commonly use RS232 or USB-serial to output data. A keyboard wedge lets that data land directly in Excel, an ERP screen, a browser form, or custom software.

Why I Built One

I work around a lot of manufacturing equipment. Some devices have modern APIs. Plenty do not. They just spit out serial data and expect you to deal with it.

For quick data collection, opening a terminal window is fine. For real production use, that gets old fast. Operators need the measurement to appear in the right field, formatted correctly, with minimal clicking and no manual retyping.

This is also helpful when the data is needed in a spreadsheet or database that does not have a direct integration. That is where a Windows serial keyboard wedge makes sense.

The Basic Flow

The application has three main jobs: 

Serial Device  ->  COM Port Reader  ->  Parser / Formatter  ->  Keyboard Output

First, the program opens a COM port using the correct serial settings. Then it listens for incoming data. Once a complete message is received, the software can clean it up, convert it, add units, append Enter or Tab, and finally send it to whatever application currently has focus.

On Windows, that last step can be handled with keyboard simulation. In a C# WinForms application, this makes the tool feel like a normal desktop utility instead of a heavy industrial software package.

Serial Port Settings Matter

One of the biggest gotchas with serial devices is that the COM settings have to match. If the baud rate, parity, data bits, or stop bits are wrong, the data will either be garbage or will not read correctly at all. 

Baud Rate: 9600
Data Bits: 8
Parity: None
Stop Bits: One
Handshake: None

Those settings are device-specific. Some instruments are simple 9600-8-N-1 devices. Others use odd parity, different stop bits, hardware flow control, or custom framing.

A good wedge needs to make those settings visible and easy to change.

Reading From the COM Port

In C#, the built-in SerialPort class is usually enough to get started. You open the port, subscribe to incoming data, and buffer the received bytes until a complete message is ready. 

serialPort = new SerialPort();

serialPort.PortName = "COM3";
serialPort.BaudRate = 9600;
serialPort.DataBits = 8;
serialPort.Parity = Parity.None;
serialPort.StopBits = StopBits.One;

serialPort.DataReceived += SerialPort_DataReceived;
serialPort.Open();

The important part is not just reading bytes. The important part is knowing when a complete measurement has arrived. Some devices terminate with a carriage return. Others send a fixed-length frame. Some include signs, decimal places, units, or status characters.

Parsing the Incoming Data

Raw serial data is rarely exactly what you want to type into a spreadsheet.

For example, a device might send something like this: 

ST,+0002.471 mm

For production use, maybe you only want: 

2.471

Or maybe you want the value plus an Enter key: 

2.471[ENTER]

That parsing layer is what makes the wedge useful. It can remove extra characters, validate the reading, convert units, or reject bad frames before the data gets sent to the active application.

It is best practice to console the datasheet of your device and understand the format of the serial output. That way you can write a parser that reliably extracts the needed information.

Sending It Like Keyboard Input

Once the data is cleaned up, the wedge sends it to Windows as keyboard input. That means the receiving program does not need to know anything about serial ports.

Excel just sees typed numbers. A web form just sees typed text. A legacy ERP screen just receives keystrokes. 

// this is bread and butter for a keyboard wedge. 
// it takes the formatted value and sends it to the active window as if it were typed on the keyboard.
SendKeys.SendWait(formattedValue);
SendKeys.SendWait("{ENTER}");

This is simple, but it is also powerful. It lets old equipment talk to modern workflows without needing custom integrations for every application.

Where This Helps

A serial keyboard wedge is useful anywhere measurements or device outputs need to be entered repeatedly. 

- Digital calipers
- Mitutoyo-style gauges
- Scales and balances
- Barcode scanners
- Test fixtures
- Multimeters
- Force gauges
- Custom Arduino or microcontroller devices
- PLC or RS232 equipment

In manufacturing, the value is usually not just convenience. It reduces typing errors, speeds up inspection, and makes it easier to collect consistent data.

Making It Operator Friendly

The technical side is only half of the project. The other half is making the tool easy to use on the floor.

Operators should be able to select the COM port, confirm the device is connected, see the most recent value, and know whether the wedge is actively sending data.

A simple WinForms interface works well for this kind of utility. It launches fast, runs on Windows production PCs, and does not need a browser, server, or database unless the application grows into something larger.

What I Like About This Approach

It's simple and focused.

A keyboard wedge can be extremely practical. It works with software you do not control. It works with legacy systems. It works with spreadsheets. It works with old Windows applications that are still running critical production processes.

Sometimes that is exactly what you need.

The best factory software is not always the flashiest software. Sometimes the best tool is the one that quietly removes a repetitive manual step and keeps production moving.

Project Link

I have been building this as an open-source Windows utility called SerialWedge. The project is written in C# and is meant to be a practical starting point for reading serial devices and sending the data into normal Windows applications.

I also have a project page here: SerialWedge project page.

It is still evolving, but the goal is straightforward: make it easier to get serial device data into the places people are already working.
