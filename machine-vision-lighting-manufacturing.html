Interfacing with the AmScope MD310C-BS Using toupcam.dll

By John Glatts

The AmScope MD310C-BS is a compact 3.1MP USB 2.0 C-mount microscope camera designed for inspection and measurement work. AmScope describes it as an industrial inspection camera with a standard C-mount lens port and USB connectivity for both power and data.

camera_stack

Main idea: Basic camera interface workflow.
AmScope Camera → toupcam.dll → Toupcam C# Wrapper → Your Application

The toupcam.dll

The Toupcam SDK gives you direct access to the camera instead of treating it as a generic video device. That matters when you want better control over exposure, image format, resolution, callbacks, and frame handling.

I reached out to the vendor and they sent me a ZIP file with the SDK. The SDK includes native files, and there are a lot of them. The key here is to choose the right ones for your project as there are quite a few options.

The wrapper I used states that it calls into the native toupcam.dll API through P/Invoke. The C# Toupcam class is a thin wrapper around the native API, so the SDK documentation still applies.

Project Setup

For a C# Windows application, the basic setup looks like this:

  • Add toupcam_wrapper.cs or toupcam.cs to your project
  • Place toupcam.dll next to your compiled .exe
  • Make sure your project platform matches the DLL, either x86 or x64
  • Use the Toupcam class from the wrapper to enumerate, open, and stream from the camera

The wrapper exposes methods such as EnumV2(), Open(), and OpenByIndex() for finding and opening cameras. The comments in the wrapper also note that the camera object should be created through Open or OpenByIndex, not by directly calling the constructor.

Enumerating Cameras

The first step is to see what cameras are connected.

var devices = Toupcam.EnumV2();

if (devices.Length == 0)
{
    Console.WriteLine("No Toupcam cameras found.");
    return;
}

foreach (var device in devices)
{
    Console.WriteLine(device.displayname);
    Console.WriteLine(device.id);
}

This is useful if you eventually have more than one camera connected. For a single-camera setup, opening by index is usually enough.

Opening the Camera

Toupcam cam = Toupcam.OpenByIndex(0);

if (cam == null)
{
    Console.WriteLine("Failed to open camera.");
    return;
}

Console.WriteLine("Camera opened.");

At this point, you have a camera handle managed by the wrapper. The wrapper also exposes HResult, which is useful when debugging failed SDK calls.

Using Pull Mode with a Callback

One of the most useful integration patterns is pull mode with a callback. The SDK notifies your application when an image is ready, and then your code calls PullImage to copy the frame into your own buffer.

In the wrapper, the event enum includes EVENT_IMAGE, described as a live image event. When that event arrives, you use PullImage to retrieve the frame. 

private Toupcam _cam;
private byte[] _buffer;

private void StartCamera()
{
    _cam = Toupcam.OpenByIndex(0);

    if (_cam == null)
        throw new Exception("Could not open camera.");

    _buffer = new byte[2048 * 1536 * 3];

    bool started = _cam.StartPullModeWithCallback(OnCameraEvent);

    if (!started)
        throw new Exception("Could not start pull mode. HRESULT: " + _cam.HResult);
}

private void OnCameraEvent(Toupcam.eEVENT evt)
{
    if (evt == Toupcam.eEVENT.EVENT_IMAGE)
    {
        uint width;
        uint height;

        bool ok = _cam.PullImage(_buffer, 24, out width, out height);

        if (!ok)
        {
            Console.WriteLine("PullImage failed. HRESULT: " + _cam.HResult);
            return;
        }

        Console.WriteLine($"Frame received: {width} x {height}");

        // At this point _buffer contains the image data.
        // You can copy it into a Bitmap, convert it to an OpenCV Mat,
        // run measurement code, or save it for debugging.
    }
}

Converting the Frame for OpenCV

Once the frame is in a byte array, you can convert it into whatever your application uses. For machine vision work, I usually want the image in OpenCV. 

// Example idea only. Confirm channel order and stride for your camera settings.
Mat mat = new Mat((int)height, (int)width, MatType.CV_8UC3);
Marshal.Copy(_buffer, 0, mat.Data, _buffer.Length);

Why This Matters for Measurement Systems

For a measurement system, the camera integration is only one piece of the puzzle. The real value comes from repeatability.

  • Use fixed lighting
  • Lock focus
  • Lock exposure when possible
  • Mount the camera rigidly
  • Calibrate pixels to real units
  • Save failed images for debugging

The software side needs to be boring and predictable. A callback-based image pipeline is useful because the application can react when a real frame is available instead of sleeping, polling, or guessing.

Common Issues

DLL Not Found

Make sure toupcam.dll is copied to the same folder as your executable. Also check that your application platform matches the DLL architecture.

Camera Opens in Vendor Software but Not Your App

Close the vendor software before running your application. Only one process may be able to control the camera at a time.

Callback Fires but PullImage Fails

Check the buffer size, bit depth, and image format. Also inspect cam.HResult after the failed call.

Image Looks Flipped or Rotated

The SDK exposes camera options for orientation and image processing. Depending on your optical setup, you may need to flip or rotate in software.

Python Reference

There is also a Python project called NMGRL/toupcam that provides a Python interface to ToupCam cameras. I still prefer the C# wrapper for Windows production tools, but the Python project is useful as a reference if you want to understand the SDK flow from another language.

Final Thoughts

The AmScope MD310C-BS is a useful low-cost camera for custom inspection and measurement systems. The important lesson is that serious integration should go through toupcam.dll, not just a generic webcam interface.

Once you can reliably enumerate the camera, open it, receive frame events, and pull image buffers, you have the foundation for a real machine vision system.
