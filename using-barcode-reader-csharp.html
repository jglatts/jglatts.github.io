Using a Barcode Reader in C#

By John Glatts

The Simple Trick: Barcode Scanners Act Like Keyboards

One of the easiest ways to add barcode input to a C# application is to use a basic USB barcode scanner.

A basic USB barcode scanner behaves just like a standard keyboard.

One of the easiest ways to add barcode input to a C# application is to use a basic USB barcode scanner.

I used a cheap wired USB scanner, similar to the WoneNice USB laser barcode scanner. These scanners are nice because most of them do not require any special SDK, driver, or serial communication setup.

To Windows, the scanner usually behaves just like a keyboard.

That means when you scan a barcode, the scanner simply “types” the barcode characters into whatever control currently has focus.

Why This Is Useful

For simple shop-floor apps, test fixtures, inventory tools, or internal utilities, this is perfect.

Instead of building a complicated barcode interface, the C# app can just listen for keystrokes.

The scanner reads a barcode, sends the characters, and the application decides what to do next.

Using a Prefix Character

A useful trick is to configure the barcode scanner to send a specific prefix character before the barcode data.

For example, the scanner could send: 

~123456789

In this case, the ~ character tells the application:

“A barcode scan is starting. Move focus to the barcode textbox.”

Once the program sees that special character, it can jump to the correct textbox, clear any old value, and prepare to receive the scanned barcode.

Basic C# WinForms Example

In a WinForms application, one simple way to handle this is by using the form's KeyPreview property.

This allows the form to see keystrokes before the active control handles them. 

public partial class MainForm : Form
{
    private bool barcodeMode = false;

    public MainForm()
    {
        InitializeComponent();

        this.KeyPreview = true;
        this.KeyPress += MainForm_KeyPress;
    }

    private void MainForm_KeyPress(object sender, KeyPressEventArgs e)
    {
        // Scanner prefix character
        if (e.KeyChar == '~')
        {
            barcodeMode = true;

            barcodeTextBox.Focus();
            barcodeTextBox.Clear();

            // Prevent the prefix from being typed into the textbox
            e.Handled = true;
            return;
        }

        // Scanner suffix / Enter key
        if (barcodeMode && e.KeyChar == (char)Keys.Enter)
        {
            barcodeMode = false;

            ProcessBarcode(barcodeTextBox.Text);

            e.Handled = true;
            return;
        }
    }

    private void ProcessBarcode(string barcode)
    {
        if (string.IsNullOrWhiteSpace(barcode))
            return;

        // Do something useful with the barcode
        resultLabel.Text = $"Scanned barcode: {barcode}";
    }
}

How The Flow Works

The scanner is configured to send a prefix character before the actual barcode.

When the C# application sees that prefix, it moves focus to the barcode textbox.

The rest of the scanned barcode is then typed directly into the textbox by the scanner.

Most scanners can also be configured to send an Enter key after the scan. That gives the application a clean way to know when the barcode is complete.

Example Scan Sequence

A configured scanner might send this: 

~ABC12345[ENTER]

The application sees the ~, jumps to the textbox, receives ABC12345, and then processes the barcode when Enter is received.

Why I Like This Approach

This method is simple, cheap, and reliable.

There is no special barcode API to learn. There is no serial port code. There is no custom USB HID driver. The scanner just acts like a keyboard.

For many internal engineering tools, that is all you need.

  • Plug in USB scanner
  • Configure prefix and suffix characters
  • Enable KeyPreview in C#
  • Listen for the scanner prefix
  • Move focus to the correct textbox
  • Process the barcode after Enter

Final Thoughts

Cheap USB barcode scanners are surprisingly useful for small C# applications.

Because they behave like keyboards, they can be added to a WinForms or WPF tool without much extra work.

For shop-floor software, test applications, inventory lookup tools, or quick internal utilities, this is one of those simple solutions that works better than expected.

Sometimes the best interface is not a complicated one.

Sometimes it is just a barcode scanner pretending to be a keyboard.
